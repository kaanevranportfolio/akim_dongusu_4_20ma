# T025 - circuit figures: three names per terminal (datasheet pin / SPICE model node / testbench net) + legend
Durum: BİTTİ
## İstek
Context: engineer proposal (from 01_secim). In simulation circuit figures every terminal must show three different names, so pin mix-ups between datasheet, SPICE model and testbench are visible: (1) datasheet pin name + pin number with source D<nn> p.<n>; (2) SPICE model node (position in the .SUBCKT line); (3) testbench net name. Each in its own coloured box, with a legend at the side. Colour must not be the only carrier: each kind also has its own box shape/border and a text prefix. Pin mapping data lives in the module FACTS.md as a table "Pin eşleme" (01_secim will provide it for the core parts); docs\sim\circuits.py reads it.

Steps:
1. Read root CLAUDE.md Figures section, the figures skill and docs\sim\circuits.py. Report in 5 lines at most what rule 2 says today and how circuits.py draws terminals now.
2. Define the "Pin eşleme" table format in docs\INTERFACES.md (subsection). Columns, one row per terminal: Part | Doc (D<nn>) | Page | Pkg pin no | Datasheet pin name | Model file | .SUBCKT node position (1-based) | SPICE node name | Label ([V]/[R]/[A]) | Note. Rules: datasheet columns come only from the document (label [V] after the engineer crop check, [R] before); SPICE columns come from reading the .SUBCKT line of the model file ([R], or [M] if a netlist run confirmed it); an unknown cell is written "?" and never guessed.
3. circuits.py: per terminal draw three boxes with distinct styles and prefixes: "DS" (datasheet; solid rectangle, e.g. `DS 4 OUT D01 p.5`), "SP" (SPICE model node; dashed rounded, e.g. `SP 4 out`), "TB" (testbench net; double/thick-border or hexagon, e.g. `TB VOUT_NET`). Colours from the existing palette, colour-blind safe, readable in grayscale. Legend at the side explaining the three kinds (shape + prefix + colour). A terminal where DS and SP names are unmapped or "?" shows the missing box as hatched with "?" and the figure footer lists them as "UNMAPPED TERMINALS: n". A mismatch (SPICE node position differs from the datasheet pin order by the mapping) is not an error, it is exactly what the figure shows; but a terminal present in the testbench and absent in the table is a WARNING line in the output.
4. circuits.py reads the table from a markdown FACTS.md path given by argument (e.g. `--pin-map <module>\FACTS.md`), parsing only the "Pin eşleme" section; no argument -> old behavior unchanged (backward compatible), figures still render with a footer "pin map: none".
5. Tests (offline): fixture FACTS table with 1 complete part, 1 part with a "?" cell, 1 terminal missing from the table; assert the SVG contains the three prefixes and the legend, the hatched box appears for "?", the UNMAPPED count is right, and the no-argument run is unchanged. Produce one sample SVG+PNG from the fixture in the temp dir and describe it in 3 lines (do not paste it).
6. Update root CLAUDE.md Figures rule 2 (one or two lines) and the figures skill SKILL.md: three names, prefixes/shapes, legend, source labels, "?" rule, `--pin-map` usage. Keep the existing wording otherwise.
7. Run the offline tests (unittest) and report counts; `git status` and `git diff --stat` of the paths touched.
Output: Sonuç with step 1 summary (5 lines), the table format as written, a change table (step | file:line | test), test counts, git paths, and "OPEN: none" or exact open points. No full file dumps.
